# Prototype findings (slice-2)

Written by the autopilot build routine, 2026-10-23. The prototype implements design.md approach **A**: Claude's discrete judgments in, a seeded layout computed in the browser out. The fixture's `x`/`y` are ignored.

**Verdict: GO for slice-3**, with the conditions at the end. Every must-prove statement P1 to P9 that can be checked in a sandbox is proven. The two things only a real Claude.ai chat can settle (A1 CDN/CSP and A5 sandbox file shown as the artifact) are still untested. The prototype doesn't depend on A1, and P9 keeps A5's fallback affordable.

`test-contracts/` and `out/` are gitignored. They are regenerated by:

```bash
cd skill/prototype
python3 make_test_contracts.py
python3 build_map.py ../fixtures/reference-map-jevons.json map.html
mkdir -p out && for f in variant no-xy synthetic-150; do python3 build_map.py test-contracts/$f.json out/$f.html; done
NODE_PATH=$(npm root -g) node check.cjs      # needs the playwright package and a Chromium
```

The check run used the sandbox's preinstalled Playwright 1.56.1 with Chromium 141.0.7390.37, not `npx playwright@1.48.2 install` (see decisions.md).

## What worked

- **Claims-derived geometry recovers the big picture.** Climate strategy sits next to consumer basics, the two AI topics sit together, and rebound sits beside the explainers, as in the app. The layout is deterministic and needs no embeddings, no sandbox packages and no network.
- **The claims view carries the "where do sources disagree" half of the brief well.** Ranking by qualify + dispute puts the only contested propositions first, and "no source in this sample disputes it" is stated explicitly instead of implied.
- **Fast and small.** A 25 KB template, under 40 ms of layout for 150 sources, and a 60 KB page for the full fixture.
- **The contract held up.** Every valid test contract (fixture, variant, no-x/y, synthetic-150) passed both `build_map.py` and the published JSON schema. The renderer handled every optional field without special cases in the skill.

## What didn't, or is weaker than the app

- **The map is islands, not a landscape.** The app's UMAP shows spread *within* topics and a continuum between them (`side-by-side.png`). The prototype shows tidy, packed blobs with empty space between them. The caption says so, but some readers will find it less informative. Inside a topic, the only meaning is core versus edge.
- **Distances between topics rest on a handful of propositions.** With 11 propositions, one shared claim can move a topic. At skill size (4 to 10 propositions, design.md section 6) this will be noisier. `clusters[].related` is the escape hatch: Claude can state relatedness directly.
- **The unclustered group isn't always at the bottom.** The page rotates the whole layout to fit the viewport (a pure rotation, so no distances change), and that can move the unclustered zone to a corner (`variant-1440.png`). It stays visually separate and labelled. See decisions.md.
- **The layout ignores the timeline.** Unlike the app's map, nothing on the map shows date; the timeline strip is separate.
- **The topic panel scrolls inside itself at 390 px** after about 4 topics. That's acceptable, but it's a second scroll area on a phone.

## Not tested here (needs a real Claude.ai chat)

- **A1:** whether chat artifacts have the same CSP as Claude Code artifacts. The prototype makes no external request, so this matters only if slice-3 adds a CDN library. The Claude Code page constraints were re-read on 2026-10-23 and are unchanged ([code.claude.com/docs/en/artifacts](https://code.claude.com/docs/en/artifacts#page-constraints)). The chat-side help page ([What are artifacts](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)) still says nothing about scripts or CDNs.
- **A5:** whether a file the sandbox writes can be shown as the artifact, or whether Claude must re-emit the 60 KB page itself. At 25 KB of template plus about 40 KB of data, re-emitting costs roughly 20k output tokens (my estimate, not measured). That's affordable but not free.
- **Rendering inside the artifact frame.** Headless Chromium is not the claude.ai artifact viewer (iframe sizing, the theme attribute, touch behaviour on a real phone). The page sets no fixed height and reads its width from its container, which should suit an iframe.
- **Usefulness.** The review routine can't judge whether this map helps a reader. That call is Meerav's (AUTOPILOT.md).

## Go / no-go for slice-3: GO

Reasons: every sandbox-checkable statement is proven, the arrangement matches the app for 5 of 6 topics, the generator is stdlib-only and strict, and the template is small enough that A5 failing degrades the skill rather than breaking it.

Conditions for slice-3:
1. Ship `template.html` and `build_map.py` unchanged in `skill/discourse-lens/assets/` (or `scripts/`), and tell Claude to run `build_map.py --check` before presenting the page.
2. In SKILL.md, tell Claude to write `clusters[].related` when fewer than 5 propositions span the topics, so the layout doesn't rest on one or two shared claims.
3. The dry run (slice-3) should report how the map looks at real skill size (about 25 to 40 sources and 4 to 8 propositions). This prototype only saw the 52-source app fixture and a synthetic set.
